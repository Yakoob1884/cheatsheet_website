Server

Everything you need to know to set up your first server

NPM

npm or Node Package Manager is the world's largest Software registry and is free to use.It is the default manager for Node.js and is installed alongside Node.js: https://nodejs.org/

When we first want to make our server, we first have to declare our dependencies in a file called package.json We do this to tell npm what dependencies we want to have, and that way, when we share the code, the same dependencies will pe applied for everyone else

                        
    {
        "dependencies" : {
            "express": "5.2.1"
        }
    }

When we have declared the dependencies in our package.json, we will go into the terminal and install our project dependencies with $ npm install. When we have installed, two new files will have appeared. package-lock.json and folder called node_modules that contains our dependencies

Express server

The basic structure of an Express application, consists of importing the Express module, creating an instance of the express application and starting the server

                        
    const express = require('express')
    const app = express()
    const PORT = 8080

    app.listen(PORT, (error) => {
        if (error){
            console.log(error)
            return
        }
        console.log("Server is running on port ", PORT)
    })

This code will be saved in a file called app.js, and can be run with $ node app.js in the terminal.

Nodemon

Right now we use $ node app.js to run code in the terminal, but we can also use something called nodemon.

Nodemon is a tool helps node based applications by automatically restart when file changes in the directory are detected. You can install nodemon as a development dependency or globally to your system path. 

                        
    // Install as a dependency
        npm install --save-dev nodemon

    // Install globally
        npm install -g nodemon

JavaScript Modules

Everything you need to know about Node.js modules

What are modules?

Modules are building blocks in Node.jsappliation, that makes the code into seperate file, so you organize your code into logical resuable components

To use any built-in module, we use the require() function. In Node.js any file with a .js extension is a module.

CommonJS

CommonJS modules are the original way (and the default) to package JavaScript code for Node.js and widely used today for server-side JavaScript with Node.js

CommenJS uses the require(), and local modules and JSON files can be imported using a relative path 

                        
    // app.js
    const fruitOrchard = require('./fruitOrchard.js')
    
    console.log(fruitOrchard.fruits)

    // fruitOrchard.js
    const fruitOrchard = {
        fruits: ["🍑", "🥝", "🍉", "🍒", "🍌", "🍋"]
    }

    module.exports = fruitOrchard

ES Modules

ES Modules or ESM, is the official standard format for packaging JavaScript code for reuse. Before ES Modules, Node.js exclusively used the CommonJS module format. Now we choose between CommonJS and ES Modules based on the project

If we want to use ESM, we would have to add "type": "module" to our package.json

ESM uses import instead of require()

                        
    // app.js
    import fruitOrchard from './fruitOrchard.js'

    console.log(fruitOrchard.fruits)


    // fruitOrchard.js
    const fruitOrchard = {
        fruits: ["🍑", "🥝", "🍉", "🍒", "🍌", "🍋"]
    }

    export default fruitOrchard

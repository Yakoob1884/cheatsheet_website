Rules

Rule 1: Use loop methods in JavaScript (specifically).

Rule 2: Don't use "for loops" unless if you are finger counting.

Rule 3: Use .map() if you need that data afterwards, otherwise only use .forEach() if you don't.

In modern JS, prefer array methods over traditional for loops when working with arrays. The main methods to know:

.forEach(), .map(), .filter(), .reduce(), .find(), .findIndex(), .indexOf

we use .map() to return a new list of the same size: 1:1. If we want a smaller list we use .filter(), and if we use .reduce() we get 1.

.map()

Example for .map()


    const numbers = [1, 2, 3, 4, 5]

    // Task: double the numbers
     const doubleNumbers = numbers.map((number) => number * 2)

    // Results in: [ 2, 4, 6, 8, 10 ]

.map() with objects

Example for .map()


    const countries = [
        {name: "Lesotho", gdp: 530 },
        {name: "Papua New Guinea", gdp: 1025},
        {name: "Saint Vincent and the Grenadines", gdp: 1200}
    ]
                       
     // Task: if the country is lesotho, boost the GDP with 500

    const countriesWithGDPUpdated = countries.map ((country) => ({    
        name: country.name,
        gdp: country.name === "Lesotho" ? country.gdp + 500 : country.gdp
    
    }))

    // Result 

    [
        { name: "Lesotho", gdp: 1030 },
        { name: "Papua New Guinea", gdp: 1025 },
        { name: "Saint Vincent and the Grenadines", gdp: 1200 }
    ]

Side effects

In computer science, an operation or expression is said to have a side effect if it has any observable effect other than its primary effect of reading the value of its arguments and returning a value to the invoker of the operation. - wiki

Example from earlier


    // This changes the original object
        country.gdp += 500

    // While this creates a new object
    {
        name: country.name,
        gdp: country.gdp + 500
    }

This can cause bugs, as another parts of your program might expect the original data.

.filter()

We use .filter() when we want a smaller array containing specific conditions


    // Example:
    const numbers = [1, 2, 3, 4, 5]

    const evenNumbers =numbers.filter((number) => number > 3)

    // Result: This will keep the numbers greater than 3

Rules

Rule 1: Always use loop methods in modern JS.

Rule 2: 'for loops' are only used when finger counting is needed (counting to a number).

Here are 8 arguments for why loop methods (forEach, map, filter, sort, find, reduce) are better.

Argument 1:

Brevity - loop methods are often shorter than traditional "for loops"


    // Traditional for loop
    for (let i = 0; i < numbers.length; i++) {
        console.log(numbers[i])
    }   
                        

    // .forEach() method
    numbers.forEach((number) => console.log(number))

Argument 2:

Clarity - loop methods communicate intent


    /*
     .forEach() - for each element, do this
     .filter() - keep each element that matches conditions
     .find() - find an element
    
    */

Argument 3:

No accidental indexing errors (out of bounds)

When using "for loops" you manually work with index, which creates opportunites for syntax mistakes. With .forEach() you just relie on your variables
